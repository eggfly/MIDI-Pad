# ESP32-S3 WiFi音频播放器网络稳定性修复

## 问题描述
原代码在播放FLAC文件时出现TCP连接崩溃：
```
assert failed: recv_tcp /IDF/components/lwip/lwip/src/api/api_msg.c:322 (recv_tcp: recv for wrong pcb!)
```

## 解决方案

### 1. 网络连接管理改进
- **WiFi自动重连**：添加了`WiFi.setAutoReconnect(true)`和`WiFi.persistent(true)`
- **连接状态监控**：实时检查WiFi连接状态，断开时自动重连
- **重试机制**：最多重试3次，每次间隔30秒
- **连接超时**：从20秒增加到30秒，提高连接成功率

### 2. 内存管理优化
- **缓冲区大小调整**：
  - FLAC文件：16384字节（适度大小，避免内存不足）
  - MP3/AAC文件：8192字节
  - 其他格式：4096字节
- **动态缓冲区调整**：根据错误类型自动调整缓冲区大小
- **内存不足检测**：检测内存分配失败并自动恢复

### 3. 错误处理增强
- **FLAC帧大小错误**：自动增加缓冲区到24576字节
- **网络错误**：检测连接失败、超时等错误，自动切换音频流
- **内存错误**：检测内存不足，自动减小缓冲区到4096字节

### 4. TCP配置优化
在`platformio.ini`中添加了lwIP网络栈配置：
- **TCP窗口大小**：5744字节
- **接收缓冲区**：11488字节
- **发送缓冲区**：5744字节
- **最大TCP连接**：16个
- **最大套接字**：16个
- **端口重用**：启用SO_REUSE选项

### 5. 代码结构改进
- **模块化设计**：将WiFi连接逻辑分离到独立函数
- **状态管理**：添加全局WiFi连接状态变量
- **条件执行**：只有在WiFi连接时才处理音频
- **延迟控制**：添加适当的延迟避免过快重连

## 使用方法
1. 编译并上传代码到ESP32-S3
2. 确保WiFi网络稳定
3. 系统会自动连接WiFi并开始播放音频
4. 如果连接断开，系统会自动重连

## 监控信息
通过串口监视器可以查看：
- WiFi连接状态和IP地址
- 音频格式检测和缓冲区调整
- 错误检测和自动恢复过程
- 网络重连尝试次数

## 注意事项
- 确保WiFi信号强度良好
- FLAC文件需要更多内存，建议在网络稳定时播放
- 如果仍然出现崩溃，可以尝试减小缓冲区大小
